同じ弾幕ゲームを、同じ種・同じ入力で2つ同時に動かしている。弾も火花も敵も地形のタイルも、すべて模擬ヒープ上の本物のオブジェクト。GC が走ると、そのゲームは GC の仕事量に比例した時間だけ本当に止まる。左は若い領域だけを掃除する世代別 GC、右はヒープ全体をたどる GC。

弾は画面の端で反対側に回り込み、決まった時間（弾の寿命）がたつか自機に当たると消える。画面に出せる弾は2,000発まで。

生きている弾・火花・敵・タイル もう誰も指していない死骸。GC はまだ知らないので、メモリに残っている GC がコピーした生き残り／停止中 ヒープの帯：灰は死骸、黒は生きている語

検査

  1. 成立到達できるオブジェクトはすべて残り、中身もポインタも GC なしの参照実行と一致する（左右のヒープ両方）。解放されたのは参照実行でも死んでいたものだけ0
  2. 成立記憶集合は完全：old から young へのポインタはすべて汚れたカードの上にある（世代別）0
  3. 成立各ヒープで動くゲームの出力が、GC なしの参照実行と一致する0
  4. 成立左と右のゲームは、同じフレーム番号で同じ出力を出している（止まった時間がずれても、中身は同じ）0

単位は語（4バイト）。GC の仕事量は、コピーした語、たどったポインタ、走査したカード・ルート・ヘッダの合計で、実時間ではない。停止時間は左右共通で 1,000語 = 20ミリ秒 に換算している（本物の GC より数千倍遅く見せている）。ヒープの総量は左右で同じ（世代別は eden 12,288語、survivor 4,096語×2、old は地形の1.25倍＋40,960語。非世代別はその合計を1つの空間にする）。1回の停止は、同じフレームの中で続けて起きた GC の合計（old が足りずに major GC と minor GC が続くと1回の長い停止になる）。地形マップは段・列・タイルのオブジェクトの木で、ゲームの間ずっと生きている長寿命データ。参照実行は GC を持たない普通の JS オブジェクトのグラフで、参照数で死んだ瞬間を測る。起動時のマップの読み込みと最初の5秒は、表示の前に済ませている。
